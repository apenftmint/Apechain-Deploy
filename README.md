# ApeChain Live NFT Mints (Vite Version)

This project displays live NFT mints from the ApeChain network. It has been converted to use Vite for a modern build process, making it ready for deployment on platforms like Netlify.

## Project Structure

- **`/index.html`**: The main HTML entry point, located in the project root.
- **`/src/`**: Contains all the application source code.
  - **`index.tsx`**: The main React entry point that renders the App component.
  - **`index.css`**: Global styles and Tailwind CSS directives.
  - **`App.tsx`**: The root React component containing the main application logic.
  - **`constants.ts`**: Application-wide constants.
  - **`types.ts`**: TypeScript type definitions.
  - **`/components/`**: UI components.
    - **`/admin/`**: Components related to the admin configuration panel.
  - **`/services/`**: Services for interacting with the blockchain, etc.
- **`/public/`**: Static assets that are copied directly to the build output (e.g., favicons, images).
- **`netlify.toml`**: Netlify configuration file for builds, redirects, and serverless functions.
- **`/netlify/functions/`**: Directory for Netlify Serverless Functions. **Stub examples are provided for `/api/settings`, `/api/seen-popups`, and `/api/mark-popup-seen`. These stubs use in-memory storage, which is NOT suitable for production and will reset. You MUST replace them with proper backend logic and a persistent database for a real application.**
- **`vite.config.ts`**: Vite configuration file.
- **`tailwind.config.js`**: Tailwind CSS configuration.
- **`postcss.config.js`**: PostCSS configuration (used by Tailwind).
- **`tsconfig.json`**: TypeScript configuration for the project.
- **`tsconfig.node.json`**: TypeScript configuration for Node.js-based files like `vite.config.ts`.
- **`package.json`**: Lists project dependencies and scripts.
- **`metadata.json`**: Platform-specific metadata (not part of the web app build itself).


## Development

1.  **Install Dependencies:**
    ```bash
    npm install
    # or
    yarn install
    ```

2.  **Run Development Server:**
    ```bash
    npm run dev
    # or
    yarn dev
    ```
    This will start the Vite development server, typically at `http://localhost:5173`. The app will automatically reload when you make changes.
    To test with Netlify Functions locally, use `netlify dev`.

## Building for Production

1.  **Build the Application:**
    ```bash
    npm run build
    # or
    yarn build
    ```
    This command first runs `tsc --build` to type-check the project and referenced Node.js config files, then `vite build` to compile and bundle the application. Optimized static assets will be generated in the `dist/` directory.

2.  **Preview Production Build (Optional):**
    After building, you can preview the production version locally:
    ```bash
    npm run preview
    # or
    yarn preview
    ```

## Deployment

The `dist/` directory generated by the build process contains the static files ready for deployment.

**Deploying to Netlify:**

1.  Push your project to a Git repository (GitHub, GitLab, Bitbucket).
2.  Connect your Git repository to Netlify.
3.  Netlify will use the `netlify.toml` file for build settings:
    -   **Build Command:** `npm run build`.
    -   **Publish Directory:** `dist`.
    -   **Functions Directory:** `netlify/functions`.
4.  Configure any necessary environment variables in the Netlify site settings (Site settings > Build & deploy > Environment).
5.  Deploy!

## API Endpoints & Netlify Functions

The application makes calls to relative API endpoints like `/api/settings`, `/api/seen-popups`, and `/api/mark-popup-seen`.

1.  **Implement Netlify Functions:**
    *   Create a directory named `netlify/functions/` in the root of your project.
    *   Inside this directory, create JavaScript or TypeScript files for each endpoint (e.g., `settings.ts`, `seen-popups.ts`).
    *   **IMPORTANT**: The provided template includes stub functions in `netlify/functions/` that use **in-memory storage**. This is for demonstration only to make the API calls work without error. For any production application, you **MUST** replace this in-memory logic with robust backend code that interacts with a persistent database (e.g., FaunaDB, Supabase, Firebase, PostgreSQL, MongoDB, etc.).

2.  **Netlify Rewrites:**
    The `netlify.toml` file includes a rewrite rule:
    ```toml
    [[redirects]]
      from = "/api/*"
      to = "/.netlify/functions/:splat"
      status = 200
    ```
    This rule routes frontend requests from `/api/someEndpoint` to your Netlify Function at `netlify/functions/someEndpoint.ts` (or `.js`).

3.  **Client-Side Routing (SPA Fallback):**
    The `netlify.toml` also includes:
    ```toml
    [[redirects]]
      from = "/*"
      to = "/index.html"
      status = 200
    ```
    This is vital for Single Page Applications.

**If your API is hosted externally (not as Netlify Functions):**
You would not use the `/.netlify/functions/:splat` rewrite for those external API calls. Instead, you would either:
*   Use the full absolute URLs of your external API in your frontend `fetch` calls.
*   Or, configure different proxy rewrites in `netlify.toml` to your external backend domain.
Choose the API handling strategy that fits your architecture. The provided `netlify.toml` and stub functions default to using Netlify Functions.
