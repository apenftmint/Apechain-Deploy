# ApeChain Live NFT Mints (Vite Version)

This project displays live NFT mints from the ApeChain network. It has been converted to use Vite for a modern build process, making it ready for deployment on platforms like Vercel.

## Project Structure

- **`/index.html`**: The main HTML entry point, located in the project root.
- **`/src/`**: Contains all the application source code.
  - **`index.tsx`**: The main React entry point that renders the App component.
  - **`index.css`**: Global styles and Tailwind CSS directives.
  - **`App.tsx`**: The root React component containing the main application logic.
  - **`constants.ts`**: Application-wide constants.
  - **`types.ts`**: TypeScript type definitions.
  - **`/components/`**: UI components.
    - **`/admin/`**: Components related to the admin configuration panel.
  - **`/services/`**: Services for interacting with the blockchain, etc.
- **`/public/`**: Static assets that are copied directly to the build output (e.g., favicons, images). (Currently not used for app-specific assets beyond Vite's default)
- **`vite.config.ts`**: Vite configuration file.
- **`tailwind.config.js`**: Tailwind CSS configuration.
- **`postcss.config.js`**: PostCSS configuration (used by Tailwind).
- **`tsconfig.json`**: TypeScript configuration for the project.
- **`tsconfig.node.json`**: TypeScript configuration for Node.js-based files like `vite.config.ts`.
- **`package.json`**: Lists project dependencies and scripts.
- **`metadata.json`**: Platform-specific metadata (not part of the web app build itself).


## Development

1.  **Install Dependencies:**
    ```bash
    npm install
    # or
    yarn install
    ```

2.  **Run Development Server:**
    ```bash
    npm run dev
    # or
    yarn dev
    ```
    This will start the Vite development server, typically at `http://localhost:5173`. The app will automatically reload when you make changes.

## Building for Production

1.  **Build the Application:**
    ```bash
    npm run build
    # or
    yarn build
    ```
    This command first runs `tsc` to type-check the project, then `vite build` to compile and bundle the application. Optimized static assets will be generated in the `dist/` directory.

2.  **Preview Production Build (Optional):**
    After building, you can preview the production version locally:
    ```bash
    npm run preview
    # or
    yarn preview
    ```

## Deployment

The `dist/` directory generated by the build process contains the static files ready for deployment.

**Deploying to Vercel:**

1.  Push your project to a Git repository (GitHub, GitLab, Bitbucket).
2.  Connect your Git repository to Vercel.
3.  Vercel should automatically detect that it's a Vite project.
    -   **Build Command:** Vercel will typically use `npm run build` or `yarn build`.
    -   **Output Directory:** Vercel will identify `dist` as the output directory.
    -   **Install Command:** Vercel will use `npm install` or `yarn install`.
4.  Configure any necessary environment variables in the Vercel project settings (e.g., if you were using `VITE_API_KEY`).
5.  Deploy!

## API Endpoints

The application makes calls to relative API endpoints like `/api/settings`. For these to work in production:

-   You'll need a backend service implementing these endpoints.
-   If deploying to Vercel:
    -   You can implement these as Serverless Functions within your Vercel project (by creating files in an `api/` directory at the project root).
    -   Or, you can configure rewrites in a `vercel.json` file to point these `/api/*` paths to an externally hosted backend.

Example `vercel.json` for rewrites (if backend is `https://your-backend-api.com`):
```json
{
  "rewrites": [
    { "source": "/api/(.*)", "destination": "https://your-backend-api.com/api/$1" }
  ]
}
```
This file should be placed in the root of your project.
